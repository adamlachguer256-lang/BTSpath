# BTSPath — instructions for Claude

BTSPath is an independent learning platform for BTS students in Morocco (owner: a BTS SRI student, beginner level,
limited Claude Pro usage). Static site: plain HTML/CSS/JS, no framework, no backend, no database. UI text is French.
Read README.md only if you need details not covered here. **Do not re-explore the whole project: this file is the map.**

## Hard rules
- Never modify, rename, move or delete anything in `resources/` (the owner's course files).
- Never invent course content. Quiz questions and terminal steps come ONLY from the chapter's extracted text.
  If the text is too thin (screenshots), say so instead of filling gaps.
- Read a chapter's content only through `tools/extract_text.py` (never open PDFs/PPTX directly: too expensive),
  and only for the chapters the owner asks for.
- `extracted/` is private (gitignored). Never publish it.
- No personal name anywhere in the site, no ®, no claim of official affiliation.
- Save usage: no long explanations, no re-reading files you just wrote, no reading big files you don't need.
  The owner writes in simple English: answer in simple English.

## Map
- `data/manifest.json` — every course file (id, subject, semester, label, path). GENERATED by
  `python tools/build_manifest.py`. Chapter ids look like `linux-s3-chap-8-lvm`, `sep-s1-s41-chap3`.
- `data/quizzes/index.json` + `data/quizzes/<id>.json` — quizzes (engine: `assets/js/quiz.js`).
- `data/labs/index.json` + `data/labs/<id>.json` — guided terminals (engine: `assets/js/terminal.js`).
- `assets/js/app.js` pages/router · `store.js` localStorage · `subnet.js` IPv4/VLSM tool · `style.css` design.
- `sw.js` offline cache: **bump `VERSION` (btspath-vN) whenever assets/ or data/ files change.**

## Workflow: "do chapter X" (one chapter at a time, or a small batch of the same subject)
1. Find the chapter's id and path: `grep -i "<keyword>" data/manifest.json`.
2. Extract: `python tools/extract_text.py "<path from resources/...>"` → read `extracted/<id>.txt`.
   If it says "probably scanned", stop and tell the owner (needs OCR, not built yet).
3. Write `data/quizzes/<short-id>.json` (format below), ~10–13 questions, all from the text.
   Choices are shuffled at runtime, so put the right answer anywhere. Add `explanation` when the text gives a reason.
4. LINUX only, if the chapter shows commands: write `data/labs/<short-id>.json` (format below).
5. Add entries to both `index.json` files with the exact `chapterId` from the manifest.
6. Validate (JSON parses, every `answer` index valid, chapterId exists in manifest), bump `VERSION` in `sw.js`.
7. Report in 3–5 lines: what was made, anything thin or unclear in the chapter.

## Quiz format
```json
{ "title": "…", "description": "Linux · Semestre 3 · Chapitre 8. Questions tirées du support de cours.",
  "questions": [ { "question": "…", "choices": ["…","…","…","…"], "answer": 0, "explanation": "…" } ] }
```
index entry: `{ "id": "linux-s3-lvm", "file": "linux-s3-lvm.json", "title": "…", "subject": "LINUX", "chapterId": "<manifest id>", "demo": false }`

## Terminal (lab) format — the owner's key requirement
**Replay the chapter's own examples, in the chapter's order, with the exact same names, devices, paths, prompt and
outputs as the course** (e.g. `/dev/hda8`, `vg1`, `clicclac`, prompt `A:/mnt#`). One step per example command.
Give each step the course section title. Copy outputs exactly from the text when the course shows them.
Last section can be the `challenge` (no hints). Reference: `data/labs/linux-s3-lvm.json`, `linux-s3-raid.json`.
```json
{ "chapterId": "<manifest id>", "title": "… — les exemples du cours", "intro": "…", "prompt": "root@serveur#",
  "steps": [ { "section": "3.a Création", "task": "…", "accept": ["exact command", "equivalent variant"],
               "hint": "…", "output": "copied from the course", "note": "optional", "prompt": "optional new prompt" } ],
  "challenge": { "section": "…", "task": "…", "accept": ["…"] } }
```
`accept` is compared after collapsing spaces: list every valid option order / long-short option variant.
Multi-command challenge: `"accept_sequence": [["cmd1"], ["cmd2"]]`. index entry: `{ "id", "file", "title", "chapterId" }`.
SEP: quiz only.
NETWORK terminal (Cisco IOS): same lab format, no engine change needed. Use the per-step `prompt` to follow the
IOS modes exactly as in the course (`Switch>` → `Switch#` → `Switch(config)#` → `Switch(config-if)#`); `enable`,
`configure terminal`, `interface …`, `exit`/`end` are steps too. Copy `show …` outputs from the course.
Accept common IOS abbreviations only if the course uses them (e.g. `conf t` for `configure terminal`).
Many NETWORK config commands are on image slides: if the extracted text has no commands, say so (needs OCR).
